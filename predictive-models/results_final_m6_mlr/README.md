# results_final_m6_mlr

**Final validated backtesting for Model 6 — LinearRegressionModel / MLR (Darts).**

Previously named `real_data_m6_mlr/`. Contains the M6 backtest results and the controlled
M4 vs M6 comparison (same pipeline, same events, same thresholds — only the learning
algorithm differs) used in the dissertation methodology.

## Scripts

| Script | Purpose |
|---|---|
| `config.py` | Hyper-parameters — identical to `../results_final_m4_lgbm/config.py` and mirrored in `production_m6/config_production_m6.py`; `EVENTS_CSV` points to the shared `../results_final_m4_lgbm/event_windows_v3.csv` |
| `real_utils.py` | Data loading (identical pipeline to M4) |
| `01_model6_mlr_continuous.py` | Continuous backtest over the full record (2024-12-30 → 2026-09-12, ~21 months); auto-detects 25 Atenção-crossing periods |
| `02_precip_gate_m6.py` | Gate sensitivity (5/10/15 mm) |
| `03_compare_m4_m6.py` | M4 vs M6 comparison plot and metrics (`compare_m4_vs_m6.*`) |
| `04_lead_time_m6.py` | Lead time analysis by alert level |
| `05_rmse_per_event.py` | RMSE per test event, M4 vs M6 (`rmse_per_event*`) |
| `06_compare_fullsim.py` | RMSE over the full continuous simulation (`compare_m4_vs_m6_fullsim.*`) |

## Caveat — which numbers are the published ones

`compare_m4_vs_m6.png` and `compare_m4_vs_m6_fullsim.png` compute the RMSE over **every step of
the record**, so they mix the training period (~79 % of the record, where the flexible M4 fits
much better) with the test period, and their alert counts include the training events. They do
**not** reproduce the dissertation's RMSE table, which reports the **out-of-sample** (test,
from 2026-05-01) and in-sample values separately, nor its test-only detection table. The
`lead_time_comparison_m4_vs_m6.png` figure, in contrast, covers the test events only.
Any claim about relative model performance must use the out-of-sample numbers in
`Documentation/predictive_model/base_reescrita_dissertacao.md` (authoritative) or the audit
report generated by `../plot_events_audit_pdf.py`.
